## 概念

### Java的特点

- 平台无关

Java编译器将源码编译成字节码（bytecode），此字节码可以在`任何安装了Java虚拟机（JVM）的系统上运行`

- 面向对象

Java是一门面向对象的编程语言，`几乎一切都是面向对象`。面向对象编程（OOP）使得代码更容易维护和复用，如类与对象，封装，继承，多态，抽象等

- 内存管理

Java有自己的`垃圾回收机制`，`自动管理内存和回收不再使用的对象`，这样开发者可以不用手动管理内存，从而减少内存泄漏和其他内存的问题。

### Java的优势与劣势

优势：

1、跨平台性：因为JVM的存在，可以实现一次编写导出运行。

2、面向对象：使得代码更加可复用和维护。

3、生态特别强：国内的生态过于完善，有各种框架、组件库、工具，社区也十分活跃。

4、内存管理：有自己的垃圾回收机制，自动管理内容，自动回收不再使用的对象，对开发者很友好。

5、多线程支持：内置的线程池机制，方便并发编程。

缺点：

1、性能问题：虽然JVM又花了很多，但是相比C++或者Rust这种原生编译语言，开销很大，尤其在微服务场景下，启动时间长。

2、语法繁琐

Java的[样板代码很多](比如一个类，我们需要有构造函数，geter,seter方法，各种括号，类型说明，有时还会需要equals(),hashCode(),toString())，之前没有lambda的时候更麻烦，现在有了但是比起Python不够简洁（比如像在Python中，还会有语法糖）。

3、内存消耗

JVM本身就比较占内存，对于资源有限的环境不太友好。

### Java为什么是跨平台的

Java之所以可以跨平台，离不开我们的JVM。

`JVM是一个软件，其在不同的系统有不同的版本。`我们编写的Java源代码通过编译(javac)后会生成.class文件，也叫做字节码（bytecode）文件。`Java虚拟机就是负责将字节码文件，翻译成特定平台下的机器码进行运行`。因此，只要在不同的平台安装对应的JVM，就可运行字节码文件，运行我们编写的Java程序。

编译的结果不是生成机器码，而是生成字节码，字节码不能直接运行，必须通过JVM翻译成字节码才可以运行。不同平台生成的字节码文件是一样的，但是由JVM翻译成的机器码却不一样。

跨平台的是Java程序，而不是JVM。JVM是用C++开发的，`编译后的机器码，不能跨平台，我们可以说编译后的字节码文件可以跨平台`，不同平台下需要安装不同版本的JVM。

### JVM,JRE,JDK之间的关系

![image-20240725230247664](https://cdn.xiaolincoding.com//picgo/image-20240725230247664.png)

- JVM是Java虚拟机，`是Java程序运行的环境`。它负责将Java字节码（由Java编译器生成）解释或编译成机器码，并执行程序。JVM提供了内存管理、垃圾回收、安全性功能，使得Java具有跨平台性。
- JDK是Java开发工具包，是开发Java程序所需的工具集合。它包含JVM，编译器（javac），调试器（jdb）等开发工具、以及一系列的类库。JDK提供了`开发，编译，调试和运行`Java程序所需要的全部工具和环境
- JRE`是Java运行时环境`，是Java程序运行时的最小环境。它包含了JVM和一组Java类库，支持程序的运行。JRE不包含开发工具，只提供Java程序运行所需的运行环境。

### JVM和Java的区别

Java是一门编程语言，JVM是平台。一个是写代码的工具，一个是跑代码的环境。

Java之所以能够跨平台（`一次编译，到处运行`），和我们的JVM有关，我们的编译器将源代码编译成字节码文件（.class）后，然后我们在不同的平台上用不同的JVM将字节码翻译成机器码运行。

### 为什么Java编译和解释都有

![img](https://cdn.xiaolincoding.com//picgo/1715928000183-44fc6130-8abc-4f0b-8f6d-79de0ab09509.webp)

编译

Java源代码会被编译器（Javac）编译成平台无关的字节码（.class）文件，这发生在程序运行之前。

解释/JIT

JVM启动后由解释器逐条解释执行字节码；同时JVM通过方法调用计数器和回边计数器识别热点代码，达到阈值后由JIT编译成本地机器码并缓存到Code Cache中，后续执行直接走机器码。

所以Java既是解释型也是编译性语言，默认采用的是解释器和编译器混合的模式

### JVM是什么

JVM是Java虚拟机，它的主要工作是解释自己的指令集（即字节码）并映射到本地的CPU指令集和OS的系统调用。

JVM屏蔽了与操作系统平台相关的信息，使得Java程序只需要生成在Java虚拟机运行的目标代码（字节码），就可在多种平台上不加修改的运行，这也是Java==一次编译，到处运行==的原因

### 编译型语言和解释型语言有什么区别

- 编译型语言，会把整个源代码编译成目标平台的机器码，生成可执行文件。执行时直接运行编译后的文件。==速度快，但是跨平台性差。==
- 解释型语言，程序执行时，会逐行解释执行源代码，但不生成独立的可执行文件。通常由执行器动态解释和执行代码。==跨平台性好，但是执行速度较慢。==
- 典型的编译型语言如C、C++，典型的解释型语言如Python、JavaScript。
- 严格来说，Java属于编译型和解释型的混合，因为他是先由Javac编译成字节码再由JVM解释/JIT执行

### 值传递和引用传递的区别

在Java中，参数传递只有`值传递`这一种，不存在真正的“引用传递”

**值传递（pass by value）**。传递的是实际值的副本，适用于基本数据类型，修改的是方法内的副本，不会影响原变量的值。

**引用传递的误解。**对于对象（引用类型），传递的是对象引用的副本（而非对象本身）

`两个引用（原引用和副本）指向同一个对象`，因此`通过副本修改对象内的数据，会影响原对象`。但`如果修改副本的指向（指向新对象），不会影响原引用的指向`。

简单来说，Java中只有值传递一种。

- 基本类型传递值的副本，不会修改原有值
- 引用传递传递引用的副本，通过副本可以修改对象内容，但无法修改原引用的指向

```java
public class Person {
    String name;
    Person(String name) { this.name = name; }
}

public static void main(String[] args) {
    Person p = new Person("Alice");
    changeName(p);
    System.out.println(p.name); // 输出 "Bob" (对象内部被修改)

    changeReference(p);
    System.out.println(p.name); // 仍输出 "Bob" (原引用指向未变)
}

// 修改对象内部数据
public static void changeName(Person obj) {
    obj.name = "Bob"; // 副本和原引用指向同一个对象
}

// 修改副本的指向（不影响原引用）
public static void changeReference(Person obj) {
    obj = new Person("Charlie"); // 副本指向新对象，原引用仍指向旧对象
}
```
